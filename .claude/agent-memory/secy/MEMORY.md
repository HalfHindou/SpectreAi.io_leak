# secy memory - findings ledger + pattern library

Auto-loaded on every secy invocation via `@.claude/agent-memory/secy/MEMORY.md` include in `.claude/agents/secy/SKILL.md`.

When secy sees a pattern matching a prior finding, it references the entry ID and the fix sketch. After each audit, secy proposes updates to this file as a separate output (the user applies; secy doesn't write to memory directly without an instruction).

Source-of-truth catalogs that seed this file:
- `.claude/security/backend-log.json` (19 open backend findings as of 2026-04-30)
- `.claude/security/frontend-log.json` (15 open frontend findings as of 2026-04-30)
- `.claude/security/security-log.json` (3 external-API open findings as of 2026-03-23)
- Git log on `main` for Wave 1-5g commit SHAs.

ID format: `SEC-YYYYMMDD-NNN` for new findings, `FIX-WAVE-Nx` for shipped waves, `FIX-WEBSITE-NN` for the website repo. The 2026-05-13 audit uses three sub-namespaces: `SEC-20260513-NNN` (spectre-app secy), `SEC-20260513-W-NN` (spectre-website), `SEC-20260513-DC-NNN` (developer-control), `SEC-20260513-RT-NN` (red-team).

Severity model: **P0** = exploitable now, **P1** = exploitable in a plausible chain, **P2** = defense-in-depth gap, **P3** = hygiene.
